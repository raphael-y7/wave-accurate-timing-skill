  title: 顺势点判定总纲：级别确认→回调验证→顺势点（周线/月线/年线三级同构）
  type: framework
  source_chapter: 第四章 第七节（卷首语）；第八节（卷首语）；第九节（卷首语）；第十节（卷首语）
  source_quote: |
    "日线{c}上破{a}浪高点确立高一级别周线上涨趋势，短线日线回调验证收在{b}低点以上的点，才是周线顺势点。"（第七节）
  summary: |
    作者把"顺势点"定义成一条三级同构的判定链，每个周期都照抄同一句式，构成全书最可迁移的决策框架：
    第一步 定级别：次一级（如日线）的 {c} 上破 {a} 浪高点 → 高一级别（周线）上涨趋势"确立"；
    第二步 等回调：趋势确立后不追高，等次一级走出一段回调（"B 上移"/"（B）上移"/"{b} 上移"）；
    第三步 验位置：该回调的终点必须"验证收在"前一个同级别低点（{b}/B/（B））以上；
    第四步 落点：回调结束且验证成立的那个点，才是顺势点（=买点）；
    第五步 挂止损：止损放在刚确认的那段调整的低点以下（通常是 {a} 或 A/B 低点）；
    第六步 定目标：目标不是固定点位，而是"高一级别上涨具备结构条件之时主动出局"。
    第八节表述为"周线 C 浪上破 A 高点确立高一级月线上涨趋势……才是月线顺势点"；第九节表述为"月线（C）浪上破（A）高点确立高一级别年线上涨趋势……才是年线顺势点"。三级共用同一骨架，只是标号体系不同（{}＝日线、（）＝60 分线、大写＝周线/月线、加括号＝月线）。
  tags: [trend-confirmation, buy-point, multi-timeframe, decision-framework, 顺势点]
  task_ids: [task-01, task-04, task-11, task-18]

  title: 顺势点的趋势环境过滤：只在上级上涨趋势中找顺势点
  type: framework
  source_chapter: 第四章 第七节、第八节、第九节（卷首语第二段）；第八节二（图4-47～4-50 案例后的横向比较）
  source_quote: |
    "成功率高的周线顺势点，需在月线上涨趋势或预期上涨中寻找和等待周线“C 上移”或预期 C 上涨的顺势点。"（第七节）
  summary: |
    在 f01 的顺势点判定之上，作者加了一层"先看大环境再找点"的过滤框架：
    第一步 先定高一级别趋势的方向（月线/年线是涨是跌）；
    第二步 只在高一级别"上涨趋势或预期上涨"中去找次一级的顺势点；
    第三步 若高一级别处于下跌趋势，则次一级的上涨只是反弹，即使顺势点形态成立，成功率也低——应放弃或大幅降级（原句："在月线下跌趋势中，即使在周线上涨（反弹）顺势点交易，成功率也低。"）；
    第四步 同一级别内部再分位置优劣：处在月线（A）上涨位置不如处在（C）位置，成功率更高；
    第五步 最后叠加横向验证：结合板块指数与大盘指数，成功率再提升一级。
    这是一个"从大到小、层层筛"的漏斗，而不是单点形态识别；它把 f01 的顺势点放进趋势环境里定权重。

    三种结构在每个周期（60 分/日/周/月/年）各有一套，构成"周期×结构"的二维索引；第七、八、九节各重复一次完整矩阵（配套视频 4-1-1 至 4-9-3 逐一对应）。
